# M5.5 Daily Papers Swarm Layer Optimization Spec

## Context

Daily Papers 精读近期无法稳定自动完成，业务侧控制器已经用 artifact closeout 暂时恢复了 2026-06-04 的任务，但这暴露出 swarm layer 插件自身在批量 cron 工作流上的几个系统性短板：

1. planner 默认把所有 phase/task 串成单链，Daily Papers 这类“同一 phase 内多篇论文可并行、下一 phase 汇总再汇合”的工作流无法表达真实并发图。
2. 已安装扩展具备 queued task / runBatch / autopilot 能力，但 CLI cron 路径缺少足够的 active-run sync 和自恢复闭环，accepted/running 状态可能长期停留。
3. 开发源码曾经落后于 npm/本机已发布扩展。优化和发布前必须先以 `openclaw-swarm-layer@0.5.6` 为真实基线，再迭代到 `0.5.7`，否则修复可能落不到实际运行路径。

## Initial Source Evidence

- npm registry 当前发布线为 `openclaw-swarm-layer@0.5.6`；本机 OpenClaw 也加载 `0.5.6`，因此本修复选择 `0.5.7` 作为 patch release。
- `<SWARM_LAYER_REPO>/src/planning/planner.ts` 在 `0.5.6` 基线仍按 phase 内顺序串联任务，不能表达 Daily Papers 的同 phase 多论文并行精读。
- `<SWARM_LAYER_REPO>/src/spec/spec-importer.ts` 在 `0.5.6` 基线只读取 phase 标题和 bullet task，没有 phase execution mode。
- `<SWARM_LAYER_REPO>/src/services/orchestrator.ts` 在 `0.5.6` 基线的 batch 候选包含 queued tasks，但单任务 dispatch 选择器只看 runnable tasks，导致 queued-only drain 路径不闭合。
- `<SWARM_LAYER_REPO>/src/services/orchestrator.ts` 在 `0.5.6` 基线会在 dry-run batch 中计算 overflow queue，必须保证 dry-run 不落盘修改 workflow state。
- `<SWARM_LAYER_REPO>/src/cli/swarm-run.ts` 在 `0.5.6` 基线 dispatch 前不提供显式 active-run sync 选项；autopilot tick 有 sync 闭环，但 cron run 路径没有等价入口。
- `<SWARM_LAYER_REPO>/src/cli/swarm-status.ts` 在 `0.5.6` 基线没有 `--sync`，operator 状态查看无法顺手修正 accepted/running ACP run 的远端终态。
- `<SWARM_LAYER_REPO>/src/review/review-gate.ts` 在 `0.5.6` 基线完成 ACP sync 或 approve review 后不会统一推进 downstream planned tasks 到 ready。

## Implementation Status

`0.5.7` 基于已发布 `0.5.6` 完成本 spec 的发布必需闭环：parallel phase 语法、queued task drain、CLI active-run sync、downstream ready promotion、文档脱敏 CI、以及隔离 OpenClaw home 的本机 mini smoke test。Stale run 自动 cancel/retry 和 generic completion probes 保留为后续增强，不阻塞本次 Daily Papers cron 路径修复发布。

## Goals

- 对齐 `<SWARM_LAYER_REPO>` 开发源码与本机实际运行的 swarm layer 插件版本，确保后续修复会影响 Daily Papers 实际执行路径。
- 支持 spec 显式声明 phase 级并行语义，让 Daily Papers 的多篇论文精读任务可以并发执行，汇总任务只依赖上一 phase 全部完成。
- 让 `swarm run --all-ready --parallel N` 这类一次性 cron 调用具备自洽的 queued task drain 行为，不依赖业务脚本反复补救。
- 让普通 CLI/status 路径可以安全同步 accepted/running ACP sessions，避免长时间卡在 active 状态。
- 给 stale ACP run 提供可配置的超时、取消、重试、人工介入策略，保留完整 audit trail。
- 增强 operator 状态输出，明确区分 runnable、queued、running、stale、review_required，并给出下一步动作建议。
- 保持 plugin core 通用，不把 Daily Papers 专属的文件 artifact 判定硬编码到 swarm layer。

## Constraints

- 旧 spec 默认行为必须保持 sequential，除非 spec 显式声明 phase/task 并行语义。
- 不要求 Daily Papers 使用 autopilot 才能完成；cron + `swarm run --all-ready --parallel N` 必须是受支持路径。
- 不做无审计的 workflow state 重写；任何 closeout、timeout、retry、manual override 都必须写 run event 和 lastAction。
- 不改变 manual runner 的现有语义。
- 不把 JerryVault、Daily Papers 文件路径、论文笔记 artifact 规则硬编码进插件核心。
- 对 queue、ACP sync、planner graph 的修改必须有 unit/e2e 回归测试覆盖。
- 本地安装验证必须明确说明测试的是 `<SWARM_LAYER_REPO>` 构建产物，还是 `<OPENCLAW_HOME>/extensions/openclaw-swarm-layer` 已安装产物。

## Release Cut Acceptance Criteria

- 源码版本与运行扩展版本对齐完成；本机 mini smoke 明确验证加载路径、版本号、构建产物一致。
- 新 spec 语法可声明 parallel phase；同一 parallel phase 内任务 deps 不互相串行，下一 phase 默认依赖上一 phase 的所有 leaf tasks。
- 旧 sequential spec 的 planner 输出保持兼容，现有 sequential 测试继续通过。
- `swarm run --all-ready --parallel N` 在没有 autopilot 的情况下可以 dispatch queued-only workflow；当 active slots 释放后，再次运行可继续 drain queued tasks。
- CLI dispatch 前可启用 safe active sync；accepted/running ACP run 若远端已 completed，会更新 run record、task status、session record、workflow lifecycle。
- 无 review 的 run 完成、ACP sync 完成、review approve 后，下游依赖满足的 task 会自动推进到 `ready`。
- `swarm status --sync` 和 `swarm run --sync-active` 在 CLI 和 tool 参数面均可用。
- 文档脱敏检查进入 CI、`release:check` 和 `prepublishOnly`。

## Future Enhancement Criteria

- stale accepted/running run 超过配置阈值后可进入 safe cancel + retry 或 blocked/escalated 状态，且有 run event 和 lastAction 记录。
- Daily Papers 模拟 e2e 通过：8 个 phase-1 note tasks 并发调度、2 个 phase-2 report tasks barrier 后执行、maxConcurrent=4、ACP 完成顺序乱序、不开 autopilot，最终 workflow completed。
- `swarm status` 或报告面板显示 runnable/queued/running/stale/review_required 数量、task ids、最近 run ids，以及推荐操作。

## Non-goals

本轮不重写 OpenClaw ACP 后端，不改 Daily Papers 的论文选择逻辑，不把业务 artifact closeout 作为 swarm layer 默认完成判据。artifact probe 可以作为通用扩展点引入，但 Daily Papers 具体规则仍应留在业务 spec/controller 层。

## Phases

### Phase 0 - Source And Runtime Alignment

- Locate the authoritative source for the installed swarm layer extension and reconcile it into `<SWARM_LAYER_REPO>` without overwriting unrelated local edits.
- Add a version and install-path smoke test that compares `package.json`, `openclaw plugin list`, and `openclaw swarm doctor --json`.
- Document the local development loop for build, install, doctor, and rollback so future fixes are tested against the plugin OpenClaw actually loads.

### Phase 1 - Reproduce Daily Papers Failure As Regression Tests

- Add a Daily Papers-like fixture with 8 independent note tasks in phase 1 and 2 report tasks in phase 2.
- Add a fake ACP adapter that returns accepted first, then completed later and out of order.
- Capture current bad behavior: globally serial planner output, accepted/running runs that do not complete without sync, and queued tasks that require an external loop to drain.
- Assert that the workflow cannot require business-specific artifact closeout to reach completed.

### Phase 2 - Explicit Parallel Phase Semantics

- Extend `SpecDoc.phases` with an optional execution mode such as `sequential` or `parallel`.
- Extend the markdown importer to parse phase execution mode from a stable syntax, for example `### Phase 1 - 精读 [parallel]` or a reserved phase option line.
- Update planner graph construction so default phases stay sequential, parallel phase tasks share the previous phase barrier deps, and following phases depend on all previous phase leaf tasks.
- Update evaluator injection so evaluator/review tasks attach to the correct barrier rather than accidentally serializing unrelated coding tasks.
- Add planner tests for default sequential, explicit parallel, mixed sequential/parallel, and evaluator-enabled graphs.

### Phase 3 - Queue Drain Semantics For Cron Workflows

- Introduce a single dispatchable task selector that handles runnable and queued tasks consistently.
- Ensure queued tasks are eligible for dispatch when dependencies are still satisfied and concurrency slots are available.
- Make `swarm run --all-ready --parallel N` useful when the workflow has queued tasks but zero newly runnable tasks.
- Add tests for maxConcurrent admission, queued overflow, queued-only drain, and stable FIFO order.
- Update reports and CLI messages so "no runnable tasks" does not hide existing queued work.

### Phase 4 - ACP Active Run Sync Outside Autopilot

- Add a `syncBeforeRun` option for CLI batch and single-task run paths, defaulting to safe behavior for ACP-backed workflows.
- Add `swarm status --sync` or equivalent status sync mode that polls active ACP sessions before rendering status.
- Ensure sync transitions accepted/running to completed/failed/cancelled/timed_out and updates workflow tasks, sessions, run ledgers, reports, and progress.
- Add tests covering accepted to completed, running to completed, sync errors that should not corrupt state, and sync followed by queue drain in the same invocation.

### Phase 5 - Stale Run Recovery And Retry Policy

- Add config for stale ACP thresholds, such as `acp.staleRunMinutes`, `acp.syncBeforeRun`, and `acp.recoveryMode`.
- Reuse existing retry policy where possible so timed_out/failed runs can retry without custom business logic.
- Implement safe cancel plus retry for stale active runs when the ACP adapter supports cancel; otherwise escalate with a clear blocked state and operator recommendation.
- Record recovery actions as run events and workflow lastAction entries.
- Add tests for stale cancel, retry exhaustion, dead_letter transition, and unsupported cancel escalation.

### Phase 6 - Optional Generic Completion Probes

- Design a generic task completion probe hook that can be configured per spec or task and returns structured JSON.
- Allow probes to close stale active runs only when the probe proves external completion, preserving audit events.
- Keep the probe interface generic so Daily Papers can verify JerryVault artifacts without adding Daily Papers paths to plugin core.
- Add tests for successful probe closeout, failed probe no-op, and probe errors that escalate rather than silently completing work.

### Phase 7 - Operator Surface And Documentation

- Update README, user manual, and operator runbook with parallel phase syntax, queue semantics, sync behavior, and cron examples.
- Add status output fields for runnable, queued, running, stale, blocked, review_required, and recommended next command.
- Document when to use cron run, autopilot, manual sync, session cleanup, and artifact probes.
- Include a Daily Papers-style example spec that demonstrates phase-1 parallel notes and phase-2 barrier reports without using Daily Papers-specific paths.

### Phase 8 - Release And Local Verification

- Run unit tests and e2e tests in `<SWARM_LAYER_REPO>`.
- Build the plugin and install or link it into `<OPENCLAW_HOME>/extensions/openclaw-swarm-layer`.
- Run `openclaw swarm doctor --json` and verify the loaded plugin version and path match the freshly built artifact.
- Run the Daily Papers simulation e2e with maxConcurrent=4 and no autopilot.
- Run one real Daily Papers dry-run or limited live run, then verify workflow completion without external artifact closeout.
