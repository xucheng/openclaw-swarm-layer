# v0.5.12

ACP false-completion fix and artifact acceptance release, driven by the 2026-06-11 Daily Papers incident where embedded OpenClaw aborts were recorded as completed swarm runs with empty artifacts.

## Highlights

- **Conservative ACP terminal-state mapping** — a non-running terminal session is only `completed` when no failure evidence is attached. `lastError`, captured turn errors, and summaries containing abort/takeover signals (`This operation was aborted`, `EmbeddedAttemptSessionTakeoverError`, `promptError`, `status=error`, abort/failed/error text) now map to `failed`.
- **Failure metadata in the run ledger** — failed runs persist `failure: { source, message, upstreamState, sessionKey, backendSessionId }` so operators and controllers can distinguish embedded aborts, session errors, and validation failures from the run JSON alone.
- **First-class artifact acceptance** — tasks can declare `expectedArtifacts` (absolute paths or `**`/`*`/`?` globs; relative patterns resolve against the project root). A completed ACP run with missing artifacts is downgraded to `failed` with `failure.source: "artifact-validation"` and the task moves to `review_required`, never silently to `done`. Matched files are recorded into the run's `artifacts`.
- **Artifact-less completion warnings** — `swarm status` emits an `artifact_missing` attention item when a completed run recorded no artifacts but the task declared `expectedArtifacts` or is an artifact-producing task mentioning an absolute output path.
- **acpx keyed-store compatibility** — newer acpx builds require `api.runtime.state.openKeyedStore` during backend startup. The CLI bootstrap stub now provides an in-memory keyed store, fixing `Cannot read properties of undefined (reading 'state')` on every `swarm run --runner acp` against current acpx.
- **State schema alignment** — `run/task/workflow-state` JSON schemas now match `types.ts` (including `failure`, `expectedArtifacts`, `timed_out`, `queued`, `dead_letter`, retry/budget/rubric/contract/session fields) with an AJV regression suite.

## Verification

- `npm run release:check` — build, 65 unit files / 459 tests, 20 e2e files / 26 tests, docs redaction, release consistency, npm pack dry-run, and ClawHub package staging
- Live smoke on OpenClaw `2026.6.5` with a real ACP backend: a Daily Papers-style note-producing task completed with validated artifacts, while a sibling task that finished its process without writing the declared artifact was downgraded to `failed` (`artifact-validation`) and surfaced in `swarm status` attention; both runs used unique per-run session keys and were admitted in parallel
